# 直播电商 RPA 智能运营 Agent 项目方案

## 1. 项目定位

### 1.1 项目名称

直播电商 RPA 智能运营 Agent

### 1.2 项目定义

本项目定位为直播电商平台与企业内部系统之上的自动化运营协同层。系统不替代抖音电商、快手、淘宝直播、小红书、ERP 或 OMS 等现有后台，而是通过 RPA、规则引擎和企业知识库，自动完成跨系统数据采集、直播前巡检、异常解释、人工审批、自动修复和结果留痕。

系统需要形成以下业务闭环：

```text
电商平台后台 / ERP / Excel
            ↓
       RPA 自动采集
            ↓
 商品、SKU、库存、价格、活动数据快照
            ↓
     业务规则自动巡检
            ↓
 知识库 Agent 解释风险并给出处理建议
            ↓
         人工审批
            ↓
      RPA 执行修复操作
            ↓
   结果校验、截图留证、审计记录
```

### 1.3 目标用户

- 直播运营：创建直播任务、选择商品、发起巡检和查看准备结果。
- 商品运营：维护商品资料、价格、库存和促销信息。
- 场控人员：在开播前和直播过程中处理库存、优惠券和上下架异常。
- 客服人员：查询商品知识、售后政策和标准答复。
- 运营负责人：审批高风险操作、查看异常趋势和直播复盘结果。
- 系统管理员：配置平台账号、RPA流程、巡检规则、角色和权限。

### 1.4 核心价值

1. 减少运营人员在多个平台后台之间重复切换和核对数据的时间。
2. 在开播前发现库存、价格、优惠券、商品状态和资料缺失问题。
3. 使用企业知识库解释异常原因并生成可执行的处理建议。
4. 对改价、下架、发券等高风险操作增加人工审批和审计能力。
5. 将每次 RPA 操作、执行结果和截图统一保存，形成可追踪的业务证据。

## 3. 核心业务场景

### 3.1 直播前自动巡检

运营人员创建直播任务并选择本场商品后，系统执行以下流程：

1. 检查平台账号及登录状态。
2. 创建 RPA 采集任务。
3. 打开模拟电商后台或真实测试环境。
4. 采集商品上下架状态、SKU、库存、标价、直播价和优惠券。
5. 将采集结果写入本地数据快照。
6. 调用巡检规则逐项检查。
7. 生成通过项、警告项和阻断项。
8. Agent 引用知识库解释问题并给出处理方案。
9. 运营人员选择人工处理或提交自动修复审批。
10. 审批通过后由 RPA 执行操作并再次采集验证。
11. 输出直播准备报告。

### 3.2 直播中监控

- 定时采集重点 SKU 的库存和商品状态。
- 当可售库存低于阈值时通知场控。
- 检测商品被下架、优惠券失效或价格变化。
- 对重复异常进行聚合，避免重复告警。
- 允许场控发起补库存、切换讲解商品或下架商品的处理流程。

### 3.3 直播后复盘

- 汇总本场商品、订单、退款、库存变化和异常记录。
- 统计 RPA 任务成功率、节省的人工操作次数和失败原因。
- 识别高成交、高退款和高咨询商品。
- 根据知识库和历史结果生成下一场直播的选品与运营建议。

## 4. 系统功能规划

### 4.1 运营工作台

- 展示今日直播任务数量和准备状态。
- 展示待处理风险、待审批操作和失败的自动化任务。
- 展示近期库存、价格和优惠券异常趋势。
- 提供“新建直播任务”和“一键巡检”入口。

### 4.2 直播任务

- 创建直播任务并设置平台、账号、计划开播时间和负责人。
- 选择本场商品和 SKU。
- 设置计划价格、目标库存和必需资料。
- 发起直播前巡检。
- 查看巡检进度、风险项和最终准备状态。

直播任务建议使用以下状态：

```text
草稿 → 待采集 → 巡检中 → 待处理 → 待审批 → 可开播 → 已结束
                         ↘ 执行失败
```

### 4.3 自动化任务中心

- 展示 RPA 任务队列、执行状态、开始时间、结束时间和执行节点。
- 支持库存采集、价格采集、活动采集、商品状态检查和自动修复任务。
- 支持失败重试、取消任务和人工接管。
- 保存关键步骤截图、页面地址、输入参数和错误信息。

RPA 任务状态建议为：

```text
待执行 → 执行中 → 等待人工 → 成功
                  ↘ 可重试失败 → 重试中
                  ↘ 最终失败
```

### 4.4 风险与审批

- 按严重程度展示阻断、警告和提示风险。
- 支持指派处理人、添加备注和标记已解决。
- 对改价、商品下架、发券和库存修改创建审批单。
- 审批通过后生成不可重复执行的 RPA 任务。
- 保存申请人、审批人、执行人、执行结果和操作时间。

### 4.5 运营知识库

知识库应围绕直播业务重新组织，主要包括：

- 商品卖点、规格参数和使用说明。
- 品牌授权、质检报告和商品资质。
- 平台活动规则和价格规则。
- 直播话术、违禁词和合规要求。
- 发货、退款、换货和售后政策。
- 常见异常的标准处理流程。

所有 Agent 回答应尽量提供引用文档、文档版本和生效时间，过期资料不得作为最终执行依据。

### 4.6 运营助手

运营助手不再作为独立的通用聊天应用，而是嵌入直播任务和风险详情页，承担以下职责：

- 解释巡检失败原因。
- 引用相关平台规则和企业制度。
- 根据商品资料生成主播话术和客服答复。
- 将自然语言需求转换为结构化任务草稿。
- 给出修复建议，但不绕过审批直接执行高风险操作。

### 4.7 系统配置

- 平台账号和登录状态管理。
- RPA 执行器和浏览器环境配置。
- 巡检规则、风险等级和阈值配置。
- 商品、SKU、促销和库存基础数据维护。
- 用户、角色和权限管理。

## 5. RPA 设计方案

### 5.1 技术选择

首期使用 Playwright 实现浏览器自动化，并建设一个模拟电商后台作为稳定演示环境。真实平台接入作为扩展能力，在具备平台授权和稳定测试账号后实现。

### 5.2 执行原则

- 使用稳定属性或业务标识定位页面元素，减少对页面结构变化的依赖。
- 每个任务必须记录输入参数、执行步骤、执行结果和失败原因。
- 修改操作必须具备幂等键，防止重试时重复改价或重复发券。
- 任务失败时保存页面截图和当前步骤。
- 登录失效、验证码或页面结构变化时进入人工接管状态。
- RPA 执行完成后必须重新读取页面数据验证操作结果。

### 5.3 首期 RPA 任务类型

| 任务类型 | 输入 | 输出 |
| --- | --- | --- |
| 商品采集 | 平台账号、商品 ID | 商品状态、标题、SKU |
| 库存采集 | 商品 ID、SKU ID | 可售库存、采集时间 |
| 价格采集 | 商品 ID、SKU ID | 标价、直播价、到手价 |
| 活动采集 | 商品 ID、SKU ID | 优惠券、满减、有效期 |
| 商品下架 | 商品 ID、审批单 ID | 执行结果、验证结果、截图 |
| 价格修复 | SKU ID、目标价格、审批单 ID | 修改前后价格、截图 |

## 6. 巡检规则设计

### 6.1 风险等级

- 阻断：未处理前不允许将直播任务标记为可开播。
- 警告：允许开播，但必须由负责人确认。
- 提示：优化建议，不影响任务状态。

### 6.2 首期规则

| 规则 | 判断条件 | 默认等级 | 建议动作 |
| --- | --- | --- | --- |
| 商品已下架 | 平台商品状态不是上架 | 阻断 | 重新上架或移出本场商品 |
| SKU 缺失 | 计划 SKU 在平台不存在 | 阻断 | 检查商品映射关系 |
| 库存不足 | 可售库存低于计划阈值 | 阻断 | 补库存或调整讲解计划 |
| 价格不一致 | 平台到手价与计划价不同 | 阻断 | 提交价格修复审批 |
| 优惠券失效 | 当前时间不在活动有效期内 | 阻断 | 重新配置优惠券 |
| 价格过低 | 优惠叠加后低于最低允许价 | 阻断 | 调整活动叠加规则 |
| 资料缺失 | 缺少规定类型或有效版本的资料 | 警告或阻断 | 上传有效资料 |
| 资料过期 | 资料有效期早于开播时间 | 阻断 | 更新资料版本 |
| 违禁词命中 | 直播话术包含规则库违禁词 | 阻断 | 修改直播话术 |
| 数据过期 | 快照时间超过配置阈值 | 警告 | 重新执行采集任务 |

## 7. 技术架构

```text
Vue 运营端
    ↓ HTTP / WebSocket
FastAPI 业务服务
    ├── 直播任务服务
    ├── 巡检规则引擎
    ├── 审批与审计服务
    ├── Agent 工具调用层
    └── RPA 任务调度服务
            ↓
       Redis 任务队列与锁
            ↓
     Playwright RPA Worker
            ↓
  模拟电商后台 / 授权平台后台

MySQL：业务数据、任务、审批、审计、快照
Milvus：商品资料、平台规则、运营制度的向量检索
对象存储/本地存储：文档、任务截图和执行证据
```

### 7.1 Redis 职责

- RPA 异步任务队列。
- 同一平台账号或商品的并发锁。
- 任务幂等键和短期状态缓存。
- 直播中监控任务的调度状态。

### 7.2 Milvus 职责

- 商品资料和平台规则的语义检索。
- 为异常解释、话术生成和客服问答提供知识来源。
- 支持按商品、SKU、文档类型、版本和有效期过滤检索结果。

## 8. 前端信息架构与清理方案

### 8.1 最终一级菜单

1. 运营工作台
2. 直播任务
3. 自动化任务
4. 风险与审批
5. 运营知识库
6. 执行记录
7. 系统配置

### 8.2 删除或下线

- 与直播业务无关的通用统计图表。
- 没有真实数据来源的装饰性数据卡片。
- 独立的通用聊天页面。
- 重复的测试按钮、临时演示入口和调试信息。
- 面向普通用户展示的开发工具入口。
- 前端写死的统计数字和无法追溯来源的模拟结果。

### 8.3 合并或改名

| 当前功能 | 调整后功能 |
| --- | --- |
| 直播电商 | 直播任务 |
| 商品列表 | 本场选品 / 基础数据 |
| 库存与活动 | 平台数据快照 |
| 价格试算 | 巡检结果中的价格校验 |
| 通用知识库 | 运营知识库 |
| 通用问答 | 嵌入业务页面的运营助手 |

### 8.4 降级为系统配置

商品、SKU、库存、促销和资料关联页面继续保留，但放入“系统配置”或二级页面。它们用于查看 RPA 采集结果、人工修正映射关系和初始化演示数据，不再作为项目首页和主要卖点。

## 9. 权限与安全边界

建议增加以下业务权限：

- 查看直播任务。
- 创建和编辑直播任务。
- 发起 RPA 采集。
- 查看任务截图和日志。
- 提交修复申请。
- 审批改价、下架、发券和库存修改。
- 执行高风险 RPA 操作。
- 配置规则和平台账号。

系统不得在没有审批记录的情况下执行高风险操作。审批通过后生成的任务需要绑定审批单 ID、目标对象、预期值和幂等键，防止审批内容与实际执行内容不一致。

## 10. 数据与审计要求

每次自动化执行至少记录：

- 任务 ID、任务类型和所属直播场次。
- 发起人、审批人和执行账号。
- 目标平台、商品和 SKU。
- 执行前数据、目标数据和执行后数据。
- 每个步骤的开始时间、结束时间和状态。
- 失败原因、重试次数和人工接管记录。
- 关键步骤截图及截图哈希。
- Agent 使用的知识来源和生成的建议。

## 11. 开发路线

### 阶段一：项目收敛与前端清理

当前状态：已完成第一轮收敛。

- 调整项目名称、菜单和首页说明。
- 删除无业务价值的通用展示功能。
- 将已有商品、库存和促销功能移动到基础数据或系统配置。
- 将知识库调整为直播运营领域结构。

已完成内容：运营工作台已改为直播任务和平台快照数据驱动；商品、SKU、库存和促销已降级为直播任务的基础数据页签；独立问答、文档管理、检索调试和开发调试入口已从一级菜单移除；运营知识库保留资料管理入口，运营助手保留为二级业务能力。

完成标准：用户进入系统后能够立即理解这是直播电商自动化巡检系统。

### 阶段二：直播巡检引擎

当前状态：已完成首版确定性巡检引擎。

- 建立巡检任务、巡检批次、规则结果和风险项数据模型。
- 接入现有商品、库存、促销、价格和资料数据。
- 生成直播准备分数和“可开播/不可开播”结论。

已完成内容：巡检批次和逐条规则结果已持久化；规则覆盖场次选品、商品与 SKU 状态、库存充足度与快照时效、开播时促销、计划到手价、商品说明和宣传宣称依据；前端支持一键巡检并展示准备分、阻断项、警告项、问题说明与处理建议。

完成标准：使用人工录入的数据也能完成一条完整的直播前巡检流程。

### 阶段三：模拟电商后台与 RPA

当前状态：已完成并通过真实链路验收。

- 建设模拟电商后台。
- 开发 Playwright RPA Worker。
- 实现商品、库存、价格、活动采集。
- 保存执行步骤、截图和失败原因。

已完成内容：开发期模拟电商后台支持账号登录与商品、库存、价格、活动维护；独立 Playwright Worker 通过 Redis 队列消费采集任务，使用分布式锁防并发执行，回写库存与促销快照后自动触发巡检；前端自动化任务中心可以查看状态、步骤、错误和截图证据。真实环境已验证 Redis 入队、浏览器登录、数据采集、快照落库、自动巡检与截图保存。Worker 已增加终态幂等保护，重复队列消息不会重复采集或重复执行高风险操作。

完成标准：系统能够自动登录模拟平台，采集数据并触发巡检。

### 阶段四：审批与自动修复

当前状态：首版已完成，人工接管与自动重试策略留待工程化阶段增强。

- 建立审批单、审批步骤和执行授权数据模型。
- 实现价格修复、商品下架等可演示操作。
- 增加幂等、重试、结果校验和人工接管。

已完成内容：已建立改价、下架审批单及其状态流转；审批通过后生成绑定审批单的 RPA 执行任务；Worker 执行前读取平台现值，执行后重新采集并校验预期值，结果、步骤和截图统一留存；重复 Redis 消息与重复入队均有幂等保护。当前支持失败后人工重新入队，尚未实现验证码场景的人工接管和分级自动重试。

### 阶段五：Agent 深度集成

当前状态：已完成第三步——直播场次风险解释、人工确认的审批草稿和固定业务评测集。

- 将巡检、知识检索、价格计算和 RPA 任务封装成 Agent 工具。

- 建立 Agent 回答质量和引用准确性评测集。

已完成内容：新增只读业务工具读取指定场次、最新巡检、失败规则、审批单和 RPA 任务；运营 Agent 以确定性巡检事实为主依据，并按需检索运营知识库补充制度来源；回答同时返回风险清单、结构化处理动作、是否需要审批、知识引用、执行步骤和 token 用量。直播任务页面已嵌入本场 Agent，可直接询问阻断原因、处理优先级和审批要求。对于计划价不一致，Agent 可以生成只读审批草稿，展示目标 SKU、计划价、平台计算价和申请理由，运营人员确认后才提交审批。服务端会依据最新巡检重新构造和校验草稿，拒绝篡改价格、SKU 不匹配和旧巡检风险；审批单保存风险 ID 与证据快照，审批页可追踪来源。已建立覆盖无巡检、库存不足、价格不一致、活动失效、商品停用、资料缺失和多风险组合的 7 个固定场景，自动统计动作正确率、审批边界、目标值、错误动作率、风险追踪、解释完整率与知识引用准确率。没有巡检记录时固定引导先采集和巡检，不调用模型；Agent 不直接执行高风险写操作。

### 阶段六：监控、复盘和工程化

当前状态：阶段六已完成——运营监控、定时采集、重复告警抑制、单场复盘和工程化脚本均已落地。

已完成内容：新增近 1–365 天可配置统计窗口，按当前用户权限汇总 RPA 任务总量、排队/运行/成功/失败数、终态成功率、平均处理时长、重试任务数和任务类型分布；同步统计审批状态和每个直播场次的最新巡检结论。工作台已改为运营监控首页，直接展示可开播场次、阻断场次、RPA 成功率、失败任务、平均处理时长和待审批申请，并汇总失败任务、待审批和阻断场次异常，点击可进入对应处理页面。管理员查看全局数据，普通用户只查看自己负责的场次和发起的任务、审批。

直播中监控已增加场次级监控计划，支持 5 分钟至 24 小时采集间隔、启用、暂停和调整频率。独立 scheduler 进程锁定到期计划，以“计划 ID + 计划执行时间”生成确定性幂等键，创建只读平台采集任务并推入 Redis；Worker 完成浏览器采集、快照落库和自动巡检，结束场次的计划自动停用。监控计划、任务和最近执行时间均可在自动化任务页追踪。相同场次、任务类型和失败原因的任务异常按一条告警合并并累计发生次数，处理入口指向最新失败任务，避免工作台被重复错误刷屏。高风险改价和下架仍沿用人工审批流程，调度器不能直接创建写操作。

单场直播复盘已经接入直播任务详情。报告按场次权限实时汇总本场 SKU、计划销量、计划 GMV、全部巡检次数、最新准备分和未通过风险、RPA 任务状态/成功率/平均耗时/重试次数，以及审批状态、决策耗时和关联执行任务。运营人员可以在前端按“选品与风险、RPA 任务、审批闭环”查看，并导出带业务明细的 Markdown 归档。当前未接入真实订单和退款数据，页面与导出件均明确说明不展示实际成交额、退款率等结果指标，避免用模拟数字冒充业务成果。

工程化收尾新增四个可执行工具：`start_stack.py` 在一个终端完成迁移并启动 API、RPA Worker、定时调度器和 Vue 前端，退出时统一清理子进程；`check_runtime.py` 检查 API 依赖、数据库迁移版本、任务积压、陈旧运行任务、过期监控计划和 Redis 队列漂移；`recover_rpa_tasks.py` 默认只读预览，仅恢复 Redis 入队失败任务和无锁的超时只读采集任务，同时清理已结束任务残留的队列消息，高风险失败任务保留人工核验；`demo_live_rpa.py` 自动创建库存不足、价格不一致的演示场次，触发真实 Playwright 采集并等待自动巡检结果。真实验证中一键启动的四个进程正常运行，演示任务完成采集并生成阻断巡检，统一退出后临时端口已释放；恢复工具同时发现并清理了 11 条历史过期队列消息。

后续扩展内容：接入获得授权的真实平台测试账号、订单与退款数据，形成实际成交和售后复盘指标；在此之前不把模拟数据描述成真实业务效果。

完成标准：项目能够稳定演示，并具备可用于简历描述的工程指标。

## 12. 演示场景

推荐使用以下主线进行项目演示：

1. 运营人员创建一场直播任务并选择三个 SKU。
2. 系统调用 RPA 登录模拟电商后台。
3. RPA 发现一个 SKU 库存不足、一个优惠券失效、一个商品价格异常。
4. 巡检引擎将三个问题标记为阻断风险。
5. Agent 引用库存制度和平台价格规则解释问题。
6. 运营人员提交价格修复和商品移除申请。
7. 负责人完成审批。
8. RPA 修改模拟后台并保存截图。
9. 系统重新巡检，直播任务状态变为“可开播”。
10. 系统生成直播准备报告和完整审计记录。

## 13. 测试与验收指标

### 13.1 功能指标

- 巡检规则能够稳定复现并给出确定性结果。
- 同一审批任务重复提交不会产生重复操作。
- RPA 失败后能够记录失败步骤并按策略重试。
- RPA 修改完成后能够再次采集并验证结果。
- Agent 回答可以定位到具体知识文档和版本。

### 13.2 可量化指标

- 直播前人工核对步骤减少比例。
- 单场直播巡检耗时。
- RPA 任务成功率和平均重试次数。
- 异常发现数量和自动闭环比例。
- Agent 引用准确率和规则解释命中率。
- 高风险操作的审批覆盖率和审计完整率。
